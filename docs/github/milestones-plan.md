# GitHub Milestones Plan

## Why milestones

Milestones make roadmap progress visible and improve release discipline.

## Suggested milestones

1. `v1.0.1 - Security and quality hardening`
   - Due: +2 weeks
   - Scope: CSP/header verification, templates, scans, dependency policy

2. `v1.1.0 - Reliability and experience`
   - Due: +5 weeks
   - Scope: search UX tests, offline sync UX improvements, observability alerts

3. `v1.2.0 - Product differentiation`
   - Due: +8 weeks
   - Scope: unique experience flows and measurable activation improvements

## Milestone issue mapping

- Every issue should belong to exactly one active milestone.
- Label by area: `product`, `security`, `testing`, `observability`, `ux`, `docs`.

## Definition of done per milestone

- Lint/build/tests green
- Docs updated
- Changelog entry added
- Release tag created when scope is complete
